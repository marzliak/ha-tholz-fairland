# Release notes 0.3.0 (private release candidate)

> **Status:** private release candidate. No public release or tag exists. Do not install from an official tag until publication.

This version adds account sign-in with device discovery, automatic session recovery and reconfiguration of credentials. The integration remains cloud-only and limited to Fairland / TurboSilence heat pumps.

## What's new

- **Account sign-in:** enter the e-mail or username and password; the integration signs in, lists compatible devices and validates a device read before saving.
- **Discovery and selection:** if the account has more than one compatible device, you choose which to add.
- **Account verification:** support for verification codes and new-password challenges during setup, reauthentication and reconfiguration.
- **Automatic recovery:** when stored tokens are refused, the integration tries to renew the session without your intervention, within attempt limits.
- **Reconfigure:** credential changes are validated before the old ones are replaced.
- **Documentation in Portuguese and English:** installation, configuration, operation, dashboard, automations, privacy, updating and troubleshooting guides.
- **Examples:** a native dashboard and optional automations; no automation is active by default.

## Changes

- Credential validation performs a **state-only read** before saving. No command is sent during setup.
- Entries created by earlier versions (schemas 1.1 to 1.3) are **migrated automatically** to schema 1.4 on first start. Entry, device and entity identifiers are kept.
- Automatic recovery is the **only** supported policy.
- Old interactive-mode entries do not receive the password automatically: the integration asks for **reauthentication** when it is needed.
- Commands follow the convergence cycle described in [Operation](../operation.md#command-lifecycle): baseline read, send, check of the reported state, and restore if it does not converge.

## Security and privacy

- The integration is designed not to write passwords, tokens, SRP values, `SECRET_HASH`, authorization headers or challenge sessions to its logs or error messages.
- The documentation states explicitly that the password and tokens are kept in the config entry and in backups that include it.
- The AWS library can log full request contents at `DEBUG` level. Do not enable `DEBUG` for `botocore`, `boto3` or `urllib3`. See [Privacy](../privacy.md).

## Compatibility

- **Home Assistant:** automated tests passed on **2025.2.4** and **2026.10.1**, with mocked cloud and blocked network. The declared minimum is 2025.2.4; not every intermediate version was tested.
- **Integration icon:** from Home Assistant **2026.3**, the package can show the integration's own brand image. Earlier versions show the standard placeholder icon.
- **Installation:** manual package for this candidate. HACS installation will be documented after publication.

## Known limitations

- Cloud only. Without cloud access there is no reading and no command.
- Read-only schedules.
- Three writable items only: operation mode, target temperature and fan mode.
- Target temperature between 12 and 40 °C. The step is the one the device reports.
- 24-hour metrics are manufacturer-reported. No energy or cost measurement is provided.
- Manufacturer dependency: changes to the service or the account can make entities unavailable.
- A failed command can leave the device unavailable even after the restore attempt. Check the device physically.

## Upgrading

See [Updating](../updating.md). Take a backup before updating.
